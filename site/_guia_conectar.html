Painel Netlify

Publicar o site atualizado

No painel do Netlify, abra o site fieldo-zelo → aba Deploys. Arraste o arquivo fieldo-site-publicar.zip (ou a pasta descompactada) pra área de upload — é assim que o site é publicado hoje, sem passar por GitHub.

Esse pacote já leva as duas páginas novas (db.js atualizado e oauth-conectar.html) e não leva os arquivos internos do projeto (auditoria, testes) — eles ficavam expondo informação que não é pra ninguém de fora ver. Isso já foi corrigido nesta pasta.

por que este passo Sem isso, a tela de aprovar login (oauth-conectar.html) simplesmente não existe no site de verdade — só aqui, nesta conversa.
2
Painel Supabase · Authentication → OAuth Server

Ligar o servidor OAuth

Nessa tela existe um interruptor chamado "Habilite o servidor OAuth do Supabase". Hoje ele está desligado — ligue.

por que este passo É o Supabase quem sabe autenticar as pessoas — esse interruptor é o que liga essa peça de verdade, por trás da tela de login.
3
Mesma tela · Authorization Path

Apontar pra tela de aprovar login

Ainda na mesma tela, tem um campo Authorization Path. Preencha com o caminho abaixo:

Authorization Path/oauth-conectar.html
por que este passo É o endereço, dentro do próprio Fieldo, que mostra "Fulano quer conectar — permitir?" — a página publicada no passo 1.
4
Mesma tela · Registro de clientes

Ligar o registro automático (DCR)

Você já escolheu este caminho: em vez de cadastrar o Claude manualmente, ligue o interruptor de Dynamic Client Registration — assim qualquer app MCP (o Claude incluso) se cadastra sozinho na hora de conectar, sem você precisar copiar nenhum endereço.

⚠ vale lembrar: com isso ligado, qualquer aplicativo MCP pode se cadastrar sozinho — não só o Claude. Foi a troca consciente que você fez, por simplicidade.
